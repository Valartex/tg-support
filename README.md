# tg-support

Канал поддержки для aiogram-ботов на **темах (forum topics)** Telegram.

Одна приватная супергруппа, в ней по теме на пользователя. Пользователь пишет
боту — сообщение попадает в его тему. Вы отвечаете в теме со своего обычного
аккаунта — ответ уходит пользователю. История хранится в самом Telegram.

Одна группа обслуживает **сколько угодно ботов**: ключ соответствия — пара
(бот, пользователь), а чужие темы бот молча игнорирует.

## Установка

```bash
pip install git+https://github.com/<вы>/TGSupport.git
```

Требуется Python 3.11+, aiogram 3.15+, SQLAlchemy 2.0+.

## Подключение

```python
from tg_support import SupportConfig, SupportService, create_support_router

support_config = SupportConfig(
    support_chat_id=settings.support_chat_id,   # -100…
    engine=engine,                              # движок хост-бота: одна БД на всё
    bot_label="Otours",                         # префикс в названии темы
    entry_button="🆘 Поддержка",
    passthrough_texts=MENU_BUTTONS,             # кнопки меню выходят из режима поддержки
    user_info=get_support_user_info,            # необязательный контекст в шапку темы
)
support = SupportService(support_config)
await support.init()                            # создаёт таблицу support_threads

dp.include_router(create_support_router(support_config, support))
```

> Роутер поддержки включать **первым** — открытая сессия должна побеждать
> обычный поток сообщений бота.

Хук `user_info` получает telegram id и возвращает готовый HTML — так в шапку
темы попадает тариф, статус оплаты и всё остальное, что знает ваш бот:

```python
async def get_support_user_info(tg_id: int) -> str:
    async with async_session() as session:
        user = await get_user_by_tg_id(session, tg_id)
    return f"Тариф: <b>{user.plan}</b> до {user.plan_until:%d.%m.%Y}"
```

## Как это выглядит

**Пользователь:** нажимает «🆘 Поддержка» (или `/support`), пишет вопрос,
получает ответ в том же чате. Выйти — инлайн-кнопкой, любой кнопкой меню или
любой командой. После вашего ответа режим поддержки включается снова сам,
чтобы follow-up не потерялся.

**Вы:** в группе появляется тема `Otours · Иван Петров` с шапкой (имя, id,
username, контекст из `user_info`). Отвечаете обычным сообщением. `/close` в
теме закрывает обращение; новый вопрос от того же человека тему переоткроет.

## Настройка группы

1. Создать группу, добавить в неё бота.
2. Включить темы: Управление группой → Темы. Группа станет супергруппой,
   **её `chat_id` при этом изменится** — брать id только после этого шага.
3. Сделать бота администратором с правом «Управление темами». Права админа
   заодно снимают режим приватности — админ получает все сообщения группы,
   иначе он не увидел бы ваши ответы в темах.
4. Узнать `chat_id`: написать в группу и посмотреть `chat.id` в логах бота.

> Если ответы из тем перестали доходить до пользователей — первым делом
> проверьте, что бот всё ещё администратор. Отдельно отключать Privacy Mode
> (@BotFather → Bot Settings → Group Privacy) при наличии прав админа не нужно.

## Что делает модуль

| Ситуация | Поведение |
|---|---|
| Первое обращение | Создаёт тему + постит шапку с данными пользователя |
| Тема закрыта через `/close` | Новый вопрос переоткрывает её |
| Тему удалили вручную | Забывает связку и заводит новую тему |
| Пользователь заблокировал бота | Сообщает об этом в теме, не роняет обработку |
| Тема принадлежит другому боту | Игнорирует |
| Флуд | 10 сообщений в минуту на пользователя (настраивается) |
| Опросы, кубики, служебные сообщения тем | Не пересылает |

## Ограничения

- Состояние сессии живёт в FSM-хранилище хост-бота. На `MemoryStorage`
  (по умолчанию) после перезапуска пользователи выпадают из режима поддержки —
  ответ оператора вернёт их обратно. Для полной устойчивости — Redis-хранилище.
- Лимитер антифлуда — в памяти процесса, сбрасывается при перезапуске.
- Реакции и редактирование уже отправленных сообщений не синхронизируются.
